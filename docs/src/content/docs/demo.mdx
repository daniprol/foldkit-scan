This is the repo's [example app](https://github.com/daniprol/foldkit-scan/tree/main/example): a small sprint board with four performance bugs you can switch on. They start off, so you first see what a healthy app looks like.

Try this:

1. **Hover a row.** Only that row and the one you left flash violet. Each hover is a Message that changes the Model, and the patch touches just those two rows.
2. **Click a row, then change its status.** The row, the status buttons and the workload bars flash. Nothing else does.
3. **Watch the clock** in the header. It flashes every second, but `Ticked` is in `ignoreMessages`, so it stays out of the Frames tab.
4. **Tick "Row keys include the index"**, then search or press **New task**. Orange dashes spread over every row below the change: they were rebuilt, because their key includes their position.
5. **Tick "Heavy view on every render"** and hover around. The pill's frame time jumps past 100 ms and a Slow phase issue appears. With sound on (♪ in the panel), each stutter chimes.
6. **Open the pill** in the bottom-left corner, or press <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>S</kbd>. The Issues tab names each bug you switched on, with its fix. Untick a bug and its issue stops repeating.

Press **Add 1,000** to try a big page, **Save** to see a Command in the Frames tab, or open the demo with `?scan=off` to compare without foldkit-scan.
